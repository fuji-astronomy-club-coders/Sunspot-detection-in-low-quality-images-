# 比較モード 利用マニュアル

同じ日に撮影された最大4観測所の太陽画像を、共通の座標系で比較するための手順書です。従来の単一画像モード（`python run.py`）は変更なく使用できます。

## 1. 比較モードでできること

- `sources.yaml` に登録された最大4観測所のうち、その日に入手できた画像を1～4枚まとめて解析します。
- 黒点位置を、太陽中心を原点・太陽北を +Y・太陽半径を 1 とする共通座標に変換して CSV に出力します。
- マスクを共通座標の多角形として保存し、向きや大きさの異なる画像に同じ領域を適用できます。
- 画像解析そのものでは元画像を回転・反転・リサイズしません。マスクと黒点の座標を共通座標へ変換します。
- マスク選択画面では4画像を2×2で表示し、1画像を編集すると、選択中の範囲が残りの画像にもリアルタイムに同期します。
- 各画像にはデカルト座標の +X / +Y 北方向軸を重ねて表示します。
- 解析フロー（Raw / 周縁減光補正 / 強調 / 二値抽出）ごとに、共通方向へそろえた比較サマリー画像を保存します。
- 黒点重心の近さに基づく観測所間の自動対応付けを行い、対応した候補には共通IDを付与します。

出力座標は太陽円盤の**投影画像面上の相対座標**です。太陽表面の緯度・経度ではありません。自動対応付けは重心位置による近似であり、観測時刻差・太陽自転・差動回転を補正する物理追跡ではありません。

## 2. 共通座標系

| 項目 | 内容 |
|---|---|
| 原点 | MIN2 が推定した太陽中心 |
| +Y | 登録・入力された太陽北方向 |
| +X | 北に直交する方向 |
| 単位 | 太陽半径 = 1 |

`flip_x: false` の場合、+X は「北を上にしたときの画像右方向」です。鏡像になっている観測所は `flip_x: true` にします。北方向ベクトルだけでは鏡像かどうか判断できないため、必ず設定してください。

方向設定に使うデカルト座標系は、原点を太陽中心とし、+X を画像上の右方向、+Y を太陽北方向（上方向）とします。元画像の画素座標は左上が原点、右が +X、下が +Y です。画素中心を整数とし、`(0, 0)` は左上画素の中心です。したがって内部変換では画素Yの符号を反転します。

北方向は、次のどちらか一方で指定できます。どちらの方式でも `flip_x` は必須です。

**ベクトル指定（従来方式）**

`north_vector: {x, y}` としてデカルト座標系で指定します。`+X` は右、`+Y` は上です。元画像の画素座標は `+Y` が下向きなので、内部変換時にY成分の符号を反転します。ベクトルの長さは使用せず方向だけを使います。

**360°角度指定**

`north_angle_deg` に 0～360 の数値を指定します。角度はデカルト座標系の極角で、**0°を +X（右）、反時計回りを正方向**とします。360°は0°と同じ方向です。

| 北方向 | `north_angle_deg` |
|---|---:|
| 右（+X） | 0° または 360° |
| 上（+Y） | 90° |
| 左（-X） | 180° |
| 下（-Y） | 270° |

例: 北が画像上方向なら `north_angle_deg: 90.0` です。角度は内部で単位ベクトルへ変換され、既存の共通座標変換・マスク同期・比較処理に使用されます。`north_vector` と `north_angle_deg` を同時に指定することはできません。

> 以前の比較モード設定で `north_vector` のY成分を画像座標（下向きが正）として入力していた場合は、新しいCartesian規約へ移行するときにY成分の符号を反転してください。たとえば、以前の `{x: 0, y: -1}`（画像上向き）は、現在の `{x: 0, y: 1}` です。

| 画像上で北が… | `north_vector` |
|---|---|
| 上 | `{x: 0, y: 1}` |
| 右 | `{x: 1, y: 0}` |
| 下 | `{x: 0, y: -1}` |
| 左 | `{x: -1, y: 0}` |
| 右上 | `{x: 1, y: 1}` |

## 3. 初回の準備

### 3-1. `source_input/` を用意する

比較データを保存する入力データルートを任意の場所に作ります。既定の場所はプロジェクトルートの `source_input/` ですが、リポジトリ外（別ドライブやネットワークフォルダーなど）でも構いません。このフォルダー直下に `sources.yaml` と日付フォルダーを配置します。

`python run.py --compare` の初回実行では、既定の `source_input/` がなければ自動作成され、フォルダー選択ダイアログがそこから開きます。ダイアログで別の場所へ移動しても構いません。プロジェクトルート直下の既定フォルダーだけが `.gitignore` の対象です。リポジトリ外に置いた入力データは、そもそもこのリポジトリには含まれません。

### 3-2. `sources.yaml` を作る

`docs/templates/sources.example.yaml` を入力データルート直下の `sources.yaml` にコピーし、4観測所の情報を実際の値に書き換えます。

```yaml
sources:
  - source_id: source_01
    display_name: "観測所A"
    orientation_policy: fixed
    north_angle_deg: 90.0
    flip_x: false

  - source_id: source_04
    display_name: "観測所D"
    orientation_policy: per_sample
```

- 観測所は**ちょうど4か所**登録します。`source_id` は重複不可で、運用開始後は変更しないでください。
- `orientation_policy: fixed`: 向きが変わらない観測所です。`north_vector` または `north_angle_deg` と `flip_x` をここに登録し、全日付で再利用します。
- `orientation_policy: per_sample`: 向きが変わりうる観測所です。日付ごとの `comparison.yaml` に `north_vector` または `north_angle_deg` のどちらか一方と `flip_x` を入力します。テンプレートの4か所目はこの方式です。
- 固定方向を日付別に上書きすることはできません。固定方向を変更する場合は `sources.yaml` を更新します。

テンプレートの方向・観測所名は架空の入力例です。実際の観測画像で北方向と鏡像の有無を確認して登録してください。

## 4. 日付ごとの準備

### 4-1. 日付フォルダーを作る

入力データルートの下に `YYYYMMDD` 形式のフォルダーを作ります。既定の場所を使う場合の例: `source_input/20261102/`。

**フォルダー名が比較日付の唯一の情報源**です。`comparison.yaml` や各サンプルには日付を書きません。

### 4-2. 画像を置く

その日に入手できた画像だけを日付フォルダーに置きます。ファイル名は自由です。対応形式は `.tif` / `.tiff` / `.fits` / `.fit` / `.fts` で、2次元のグレースケール画像です。

### 4-3. `comparison.yaml` を書く

`docs/templates/comparison.example.yaml` を日付フォルダーへコピーして編集します。入手できた観測所だけを記載します。`samples` の件数は日付フォルダー内の対応画像ファイル数と一致させてください。4件固定ではありません。各 `source_id` は `sources.yaml` に登録済みである必要があり、未登録IDがある場合は比較全体がエラーになります。

```yaml
# 省略可。省略時は初回に作成した共通マスクを使用します。
# mask_template: "../mask_templates/default.json"

samples:
  - source_id: source_01
    image: "source_01.tif"
    pixel_scale_arcsec_per_pixel: 0.60

  - source_id: source_04
    image: "source_04.tif"
    pixel_scale_arcsec_per_pixel: 0.80
    north_angle_deg: 90.0
    flip_x: false
```

| 項目 | 必須 | 説明 |
|---|---|---|
| `source_id` | 必須 | `sources.yaml` に登録したID。同じ日付内で重複不可 |
| `image` | 必須 | 日付フォルダーからの相対パス |
| `pixel_scale_arcsec_per_pixel` | 必須 | 有限かつ正の数値。画像ごとに入力 |
| `north_vector` または `north_angle_deg` / `flip_x` | per_sample のみ必須 | 方向はどちらか一方、`flip_x` と合わせて指定。fixed の観測所では指定不可 |
| `mask_template` | 任意 | 日付フォルダーからの相対パス |

ピクセル分解能は、太陽の角半径（MIN2 の半径 × 分解能）の妥当性確認に使います。結果が 900～1000 秒角を外れると警告が出ますが、処理は継続します。X・Y 別のピクセル分解能には未対応で、等方ピクセルを前提とします。

## 5. 実行方法

### フォルダー選択ダイアログから

```powershell
python run.py --compare
```

フォルダー選択ダイアログは既定の `source_input/` から開きます。比較する日付フォルダーを1つ選びます。入力データが別ドライブなどにある場合は、ダイアログからその場所へ移動して選択できます。

### コマンドラインで指定

```powershell
python run.py --compare source_input/20261102
```

相対パスはプロジェクトルート基準です。絶対パスならリポジトリ外の任意の場所を指定できます。空白を含むパスは引用符で囲みます。選択した日付フォルダーの**親フォルダーが入力データルート**として扱われ、その直下に `sources.yaml` が必要です。日付フォルダー内には `comparison.yaml` と画像を配置します。画像は日付フォルダー内、`mask_template` は入力データルート内を指定してください。

実行では入力を検証した後、`comparison.yaml` の記載順に有効なサンプルを処理し、結果一覧を表示します。1回の実行で処理できる日付フォルダーは**1つ**です。複数日を比較するときは日付ごとに実行してください。

Windows では次のように `run.bat` からも起動できます。既存の `.venv` があれば標準で使用し、なければシステムPythonを使用します。

```bat
run.bat --compare
run.bat --compare source_input\20261102
run.bat --venv --compare source_input\20261102
run.bat --compare "E:\SolarData\20261102"
```

`python run.py`（引数なし）および `run.bat`（引数なし）は従来どおり単一画像モードで、動作・出力は変わりません。

## 6. 共通マスク

マスクは元画像の pixel 座標ではなく、**共通座標の多角形**として保存します。画像の向きが異なると、元画像上の矩形は別の画像では回転した四角形になるためです。

### テンプレートを指定しない場合

1. 最初に正常処理される画像が編集画面になり、2×2の4画像表示が開きます。未提供・読み込み不能の観測所はプレースホルダーになります。
2. 編集画面で除外したい領域をドラッグします。編集画像には矩形、ほかの画像には各画像の太陽中心・半径・方向を使って変換した多角形が表示されます。
3. ドラッグ中もマスク範囲がリアルタイムに同期されます。各画像には +X / +Y（北）の方向軸が表示されるため、画像の向きを確認できます。
4. 確定すると編集画像の矩形が共通座標の多角形として保存され、残りの画像には各画像の pixel 座標へ逆変換して適用します。

### テンプレートを指定する場合

`comparison.yaml` の `mask_template` に JSON ファイルのパスを指定すると、選択画面を開かずにそのテンプレートを全画像へ適用します。既存テンプレートを別の日付で再利用できます。

### テンプレートの構造

```json
{
  "schema_version": 1,
  "coordinate_system": "solar_disk_normalized",
  "created_from": {
    "source_id": "source_01",
    "image": "source_01.tif"
  },
  "regions": [
    {
      "id": 1,
      "vertices": [
        [-0.25, 0.10],
        [0.15, 0.10],
        [0.15, 0.35],
        [-0.25, 0.35]
      ]
    }
  ]
}
```

`created_from` には作成元の観測所・画像・日付・太陽 geometry・北方向・`flip_x` が履歴として残ります。座標の正本は `regions` の共通座標です。

マスクに1画素でも重なる黒点候補は、候補単位で丸ごと除外されます。複数マスクに重なる候補は1回だけ除外し、該当するすべてのマスク番号を記録します。画像の外にはみ出す領域は画像内へ切り詰めて適用します。境界判定は `Mask.boundary_policy` の `overlap` / `centroid` / `contained` に従います。

## 7. 出力ファイル

```text
results/session_YYYYMMDD_HHMMSS_xxxxxx/
├─ run_*.log
├─ run_*.json
├─ comparison_summary.json
├─ comparison_summary_raw.png
├─ comparison_summary_limb_corrected.png
├─ comparison_summary_emphasized.png
├─ comparison_summary_binary.png
├─ source_01/                         # 解析画像・観測所ごとのサマリー
├─ source_02/
├─ image_coordinates/
│  ├─ comparison_sunspot_statistics.csv
│  ├─ comparison_sunspot_exclusion_list.csv
│  └─ source_01/                      # 画像座標の個別CSV
└─ common_coordinates/
   ├─ comparison_sunspot_statistics.csv
   ├─ comparison_sunspot_exclusion_list.csv
   └─ source_01/                      # 共通座標の個別CSV
```

- 未提供・スキップ・失敗した観測所の出力フォルダーは作成されません。
- `image_coordinates/` には画像左上原点・右が +X・下が +Y の pixel 座標CSVを保存します。`common_coordinates/` には太陽中心原点・+X右・+Y北・太陽半径単位の共通座標CSVを保存します。両フォルダーは同じ階層構成で、観測所別CSVと統合CSVを含みます。
- 共通座標CSVでは重心・外接矩形を共通座標へ変換します。面積は元画像の画素数のままです。除外理由の詳細に含まれる `*_px` の列・JSONは pixel 座標のままです。
- 統合 CSV の先頭には `source_id` / `source_name` / `image` が追加されます。統合 CSV に入るのは処理に成功した観測所だけです。比較日はフォルダー名と `comparison_summary.json` で確認してください。
- `comparison_summary_*.png` は Raw / 周縁減光補正 / 強調 / 二値抽出の各段階で4画像を共通方向へ回転表示した比較画像です。元画像ファイルや解析入力画像は変更しません。
- 自動対応付けは共通座標上の重心距離を使います。対応許容距離は太陽半径の 0.025 倍です。同じ観測所から2候補が同一共通IDへ入らないよう制約し、複数観測所の候補を共通ID `CS0001` の形式で記録します。対応しない候補は `unmatched` です。
- `comparison_summary.json` には比較日付、登録4観測所、各観測所の状態と理由、太陽中心・半径・角半径、分解能、方向、変換行列、検出数、マスク情報、対応付けのアルゴリズム・許容距離・対応数、サマリー画像のファイル名、出力先、全体ステータスが記録されます。

各出力の詳細な列定義は [CSV 出力ガイド](csv_output_guide.md) を参照してください。

## 8. 実行ステータス

サンプル単位:

| 状態 | 意味 |
|---|---|
| `success` | 処理に成功 |
| `not_provided` | `comparison.yaml` に記載がない。エラーではありません |
| `skipped_invalid_input` | 入力不備により、そのサンプルだけスキップ |
| `failed_processing` | 処理中に例外が発生。他のサンプルは続行 |

全体:

| 状態 | 条件 | 終了コード |
|---|---|---|
| `success` | 登録4観測所すべてが入力され、すべて成功 | 0 |
| `partial_success` | 1件以上成功し、未提供・スキップ・失敗がある | 0 |
| `failed` | 有効サンプルが0件、または全サンプルが失敗 | 1 |
| 入力エラー | 実行開始前の比較セット全体のエラー | 2 |

## 9. エラーと対処

**比較セット全体のエラー**（実行開始前に報告され、セッションは作られません）

| 原因 | 対処 |
|---|---|
| `sources.yaml` がない・構文不正・4か所でない・ID重複・方向設定が不正 | `sources.yaml` を修正 |
| 日付フォルダー名が `YYYYMMDD` でない・実在しない日付 | フォルダー名を修正 |
| 日付フォルダー内の対応画像数と `samples` 件数が異なる | 画像と `samples` を1件ずつ対応させる |
| `comparison.yaml` の `source_id` が `sources.yaml` に未登録 | `sources.yaml` に登録するか、IDを修正 |
| `comparison.yaml` がない・`samples` が空・未対応キーがある | `comparison.yaml` を修正 |
| `mask_template` で指定したファイルがない | パスを修正するか項目を削除 |

**サンプル単位のスキップ**（該当サンプルのみ。残りは処理されます）

| 原因 | 対処 |
|---|---|
| 同じ `source_id` が複数行ある | 該当IDの全行がスキップされるため、1行にする |
| 画像がない・対応外形式・読み込めない・2次元でない | ファイルを確認 |
| 分解能が未入力、0以下、NaN、無限大 | 正の数値を入力 |
| `per_sample` で方向項目が欠落・不正 | `north_vector` または `north_angle_deg` のどちらかと `flip_x` を入力 |
| `fixed` で日付別の方向を指定 | 日付側から削除し、向きを変える場合は `sources.yaml` を更新 |
| サンプルに未対応キーがある | キーを削除 |

## 10. 注意事項

- 北方向ベクトルまたは角度の入力誤差は、マスク位置と黒点座標の両方に影響します。`north_angle_deg` は0°が右、90°が上で、反時計回りに増加します。
- `flip_x` が誤っていると、黒点位置が左右反対になります。新しい観測所の設定後は、既知の黒点が観測所間で一致するか確認してください。
- MIN2 の太陽中心・半径が不正確な画像では、共通座標も不正確になります。角半径の警告や出力画像を確認してください。
- ピクセル分解能はユーザー入力値です。誤りは角度スケールの確認や将来の物理単位換算に影響します。
- 画像ごとの観測時刻は保存せず、太陽自転・差動回転の補正は行いません。
- 固定観測所の向きを変更するときは、`sources.yaml` を更新してください。過去の実行ログには、その実行で実際に使われた向きが残ります。

## 11. 暫定仕様・未確定事項

| 事項 | 現在の動作 |
|---|---|
| 観測所の正式ID・表示名 | `source_01` ～ `source_04` の仮ID・仮名称。実際の値に変更可能 |
| 3観測所の北方向・`flip_x` | テンプレートの架空値。実際の値の登録が必要 |
| 共通 +X の向き | `flip_x: false` で「北を上にしたときの画像右方向」。天文学上の東西との対応は未確定 |
| ピクセル分解能 | 画像ごとに単一の `arcsec/pixel` を入力。X・Y別は未対応 |
| マスクテンプレート共有 | 日付フォルダーで指定。省略時は基準画像から作成 |
| 比較 CSV の指標 | 画像座標と共通座標の重心・外接矩形・面積。面積はpixel単位 |

未対応の後続課題は、北方向の自動推定、heliographic座標、太陽自転・差動回転補正、異方ピクセル、複数日付の一括実行（`--compare-all`）です。自動対応付けは重心距離による初期対応で、物理的な黒点追跡や時刻差補正ではありません。

人工画像での単体テストは追加していますが、実観測画像での MIN2 と北方向入力の妥当性、および各観測所の実際の向き・`flip_x` は、実データで確認する必要があります。自動対応付けの許容距離は初期値であり、観測分解能やMIN2の誤差を含む実データで妥当性を確認してください。比較モードで `Display.show_final_image: true` に設定しても、最終確認画面には多角形マスクの塗りつぶしは表示されません。
