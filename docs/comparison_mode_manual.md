# 比較モード 利用マニュアル

同じ日に撮影された最大4観測所の太陽画像を、共通の座標系で比較するための手順書です。従来の単一画像モード（`python run.py`）は変更なく使用できます。

このマニュアルは次の読み方を想定しています。

- **初めて使う人**: §1（概要）→ §2（クイックスタート）→ §4・§5（準備）→ §6（実行）の順に読み、実際に1日分を動かしてください。
- **設定値の意味を確認したい人**: §3（座標系）、§5（設定ファイルの仕様）、§11（設定）を参照してください。
- **出力を使って解析する人**: §9（出力ファイル）、§10（対応付け）、[CSV出力ガイド](csv_output_guide.md) を参照してください。
- **エラーが出たとき**: §12（実行ステータス）、§13（エラーと対処）を参照してください。

## 1. 比較モードの概要

### 1-1. できること

- `sources.yaml` に登録された最大4観測所のうち、その日に入手できた画像を1～4枚まとめて解析します。
- 黒点位置を、太陽中心を原点・太陽北を +Y・太陽半径を 1 とする共通座標に変換して CSV に出力します。
- マスクを共通座標の多角形として保存し、向きや大きさの異なる画像に同じ領域を適用できます。
- 画像解析そのものでは元画像を回転・反転・リサイズしません。マスクと黒点の座標を共通座標へ変換します。
- マスク選択画面では4画像を2×2で表示し、1画像を編集すると、選択中の範囲が残りの画像にもリアルタイムに同期します。
- 各画像にはデカルト座標の +X / +Y 北方向軸を重ねて表示します。
- 解析フロー（Raw / 周縁減光補正 / 強調 / 二値抽出）ごとに、共通方向へそろえた比較サマリー画像を保存します。
- 黒点重心の近さに基づく観測所間の自動対応付けを行い、対応した候補には共通IDを付与します。

### 1-2. 比較の対象と限界

出力座標は太陽円盤の**投影画像面上の相対座標**です。太陽表面の緯度・経度ではありません。自動対応付けは重心位置による近似であり、観測時刻差・太陽自転・差動回転を補正する物理追跡ではありません。詳しくは §10 と §15 を参照してください。

### 1-3. 用語

| 用語 | 意味 |
|---|---|
| 観測所 | `sources.yaml` に登録する画像の提供元。`source_id` で識別する |
| 入力データルート | `sources.yaml` と日付フォルダーを置くフォルダー。既定は `source_input/` |
| 日付フォルダー | `YYYY-MM-DD` 形式のフォルダー。1回の実行で1つを処理する |
| サンプル | `comparison.yaml` の `samples` の1行。1観測所・1画像に対応する |
| 共通座標 | 太陽中心が原点、+Y が北、太陽半径が 1 の座標（§3） |
| 共通マスク | 共通座標の多角形で保存したマスク（§8） |
| MIN2 | 画像から太陽中心と半径を推定する処理（`src/module/MIN2ver2.py`） |
| セッションフォルダー | 実行ごとに作られる出力フォルダー（§9） |

## 2. クイックスタート

初めて1日分を動かすまでの最短手順です。各項目の詳細は後続の節を参照してください。

1. 入力データルートを決める（例: `source_input/`）。
2. `docs/templates/sources.example.yaml` を入力データルート直下に `sources.yaml` としてコピーし、4観測所の名前・北方向・`flip_x` を実際の値に書き換える（§4）。
3. 入力データルートの下に日付フォルダー（例: `source_input/2026-11-02/`）を作り、その日の画像（1～4枚）を置く（§5-2）。
4. `docs/templates/comparison.example.yaml` を日付フォルダーへ `comparison.yaml` としてコピーし、`samples` を画像と同じ件数にして `source_id`・`image`・`pixel_scale_arcsec_per_pixel` を書く（§5-3）。
5. 実行する（§6）。

   ```powershell
   python run.py --compare source_input/2026-11-02
   ```

6. マスク選択画面が出たら、除外したい領域をドラッグして確定する（§8）。
7. 出力先のセッションフォルダーで `comparison_summary.json`、`comparison_summary_*.png`、`common_coordinates/` のCSVを確認する（§9）。

準備後のフォルダー構成の例:

```text
source_input/                         # 入力データルート（場所は任意）
├─ sources.yaml                       # 初回に1つだけ作る
├─ mask_templates/                    # 共通マスクの保存先（自動作成）
│  └─ 2026-11-02_source_01.json
└─ 2026-11-02/                        # 日付フォルダー（フォルダー名が比較日付）
   ├─ comparison.yaml
   ├─ source_01.tif
   └─ source_04.tif
```

## 3. 共通座標系

| 項目 | 内容 |
|---|---|
| 原点 | MIN2 が推定した太陽中心 |
| +Y | 登録・入力された太陽北方向 |
| +X | 北に直交する方向 |
| 単位 | 太陽半径 = 1 |

### 3-1. 単位・座標基準の一覧

| パラメータ・列 | 単位・基準 | 注意点 |
|---|---|---|
| `pixel_scale_arcsec_per_pixel` | 秒角/画素（arcsec/pixel）。画像ごとに指定 | 角半径は `solar_radius_px × pixel_scale_arcsec_per_pixel`。警告範囲 900～1000 は秒角であり、画素ではありません |
| `north_angle_deg` | 度（°）。0° = +X（右）、反時計回りが正 | 天文学で用いる位置角（北から東回り）ではありません |
| `north_vector` | 向きのみ。ベクトルの長さは無視 | +X は右、+Y は北（上）。画素座標の +Y とは向きが逆です |
| `*_px` 列（単一画像・`image_coordinates/`） | 画素（px）。左上原点、0始まり、+Y が下 | `*_common` と同じグラフへそのまま重ねると、符号・尺度が一致しません |
| `*_common` 列（`common_coordinates/`） | 太陽半径を 1 とする共通座標。太陽中心原点、+Y が北 | `area_px` は例外で、共通座標CSV内でも画素数のままです |
| 除外一覧CSVの重心・外接矩形 | `common_coordinates/` では共通座標、`image_coordinates/` では画素 | 1つの除外一覧CSVに、画素の補足列が併存する場合があります |
| `radial_*_px`、`radial_center_*_px` | 画素（px） | 共通座標CSVでも画素座標のままです |
| `excluded_by_mask_regions` 内の `x`・`y`・`width`・`height` | 画素（px） | JSON内の矩形値は元画像の画素座標です |
| `Mask.Rmask.radius_ratio`、`radial_ratio` | 無次元の比（太陽半径に対する割合） | `radial_limit_px = solar_radius_px × radius_ratio`。比と画素距離を混同しないでください |
| マスクテンプレートの `vertices` | 共通座標（太陽半径 = 1） | 単一画像モードの矩形ROIは画素座標です |
| 対応許容距離 `tolerance_normalized`（既定値 0.025） | 太陽半径の 0.025 倍 | 秒角ではありません。角半径 960 秒角の場合、約 24 秒角に相当します（換算例） |

> **注意：画素座標と共通座標は別の座標系です。** `*_px` は画像左上原点・画素単位、`*_common` は太陽中心原点・太陽半径単位です。尺度と原点の両方が異なるため、値を直接比較しないでください。

> **注意：+Y の向きが異なります。** 画素座標は +Y が下向きです。一方、共通座標と方向指定（`north_vector`）は +Y が北（上向き）です。内部変換では画素Yの符号を反転します。

> **注意：`north_angle_deg` は天文学の位置角ではありません。** この設定は 0° を +X（右）とするデカルト座標の極角で、反時計回りに増加します。北から東回りに測る位置角の値をそのまま入力しないでください。

### 3-2. 変換の考え方

画素座標 `(px, py)` から共通座標 `(X, Y)` への変換は、次の順で行われます。

1. 太陽中心 `(cx, cy)` を原点にずらす: `dx = px - cx`、`dy = -(py - cy)`（画素Yの符号を反転し、+Y を上向きにする）。
2. 北方向が +Y に一致するよう回転する（`north_vector` または `north_angle_deg` を使用）。
3. `flip_x: true` なら X の符号を反転する。
4. 太陽半径（画素）で割り、無次元化する。

共通座標では太陽円盤の縁が原点から距離 1 の位置になります。したがって `X² + Y² ≤ 1` が円盤内を表します。マスクは逆変換により、各画像の画素座標へ戻して適用します。

### 3-3. 北方向と `flip_x`

方向設定に使うデカルト座標系は、原点を太陽中心とし、+X を画像上の右方向、+Y を太陽北方向（上方向）とします。元画像の画素座標は左上が原点、右が +X、下が +Y です。画素中心を整数とし、`(0, 0)` は左上画素の中心です。

`flip_x: false` の場合、+X は「北を上にしたときの画像右方向」です。鏡像になっている観測所は `flip_x: true` にします。北方向ベクトルだけでは鏡像かどうか判断できないため、必ず設定してください。

北方向は、次のどちらか一方で指定できます。どちらの方式でも `flip_x` は必須です。

**ベクトル指定**

`north_vector: {x: .., y: ..}` としてデカルト座標系で指定します。`+X` は右、`+Y` は上です。ベクトルの長さは使用せず方向だけを使います。`x` と `y` の2キーだけを持つ辞書にし、有限かつ非ゼロにしてください。

| 画像上で北が… | `north_vector` |
|---|---|
| 上 | `{x: 0, y: 1}` |
| 右 | `{x: 1, y: 0}` |
| 下 | `{x: 0, y: -1}` |
| 左 | `{x: -1, y: 0}` |
| 右上 | `{x: 1, y: 1}` |

**360°角度指定**

`north_angle_deg` に 0～360 の数値を指定します。角度はデカルト座標系の極角で、**0°を +X（右）、反時計回りを正方向**とします。360°は0°と同じ方向です。

| 北方向 | `north_angle_deg` |
|---|---:|
| 右（+X） | 0° または 360° |
| 上（+Y） | 90° |
| 左（-X） | 180° |
| 下（-Y） | 270° |

例: 北が画像上方向なら `north_angle_deg: 90.0` です。角度は内部で単位ベクトルへ変換され、共通座標変換・マスク同期・比較処理に使用されます。`north_vector` と `north_angle_deg` を同時に指定することはできません。

> 以前の比較モード設定で `north_vector` のY成分を画像座標（下向きが正）として入力していた場合は、新しいデカルト規約へ移行するときにY成分の符号を反転してください。たとえば、以前の `{x: 0, y: -1}`（画像上向き）は、現在の `{x: 0, y: 1}` です。

### 3-4. 北方向と `flip_x` の確かめ方

新しい観測所を登録したときは、次の手順で設定を確認してください。

1. 同じ日の画像で、複数の観測所に写っている大きな黒点を1つ選ぶ。
2. 比較サマリー画像（`comparison_summary_raw.png`）で、その黒点が全観測所で同じ位置にそろっているか確認する。
3. 位置が上下・左右で食い違う場合は、北方向の角度（180°ずれていないか）と `flip_x` を見直す。
4. 左右だけが逆なら `flip_x` の誤りの可能性が高く、上下も逆なら北方向が180°ずれている可能性があります。

## 4. 初回の準備（入力データルートと `sources.yaml`）

### 4-1. 入力データルートを用意する

比較データを保存する入力データルートを任意の場所に作ります。既定の場所はプロジェクトルートの `source_input/` ですが、リポジトリ外（別ドライブやネットワークフォルダーなど）でも構いません。このフォルダー直下に `sources.yaml` と日付フォルダーを配置します。

`python run.py --compare` の初回実行では、既定の `source_input/` がなければ自動作成され、フォルダー選択ダイアログがそこから開きます。ダイアログで別の場所へ移動しても構いません。プロジェクトルート直下の既定フォルダーだけが `.gitignore` の対象です。リポジトリ外に置いた入力データは、そもそもこのリポジトリには含まれません。

入力データルートは、**選択した日付フォルダーの親フォルダー**として決まります。複数の日付フォルダーを同じ入力データルートに置けば、`sources.yaml` と `mask_templates/` を共有できます。

### 4-2. `sources.yaml` を作る

`docs/templates/sources.example.yaml` を入力データルート直下の `sources.yaml` にコピーし、4観測所の情報を実際の値に書き換えます。次のコードブロックは登録内容の**一部のみを示す抜粋例**です。実際のファイルには必ず4観測所分を登録してください。向きの指定方式は観測所ごとに `fixed` または `per_sample` を選べます。

```yaml
sources:
  - source_id: source_01
    display_name: "観測所A"
    orientation_policy: fixed
    north_angle_deg: 90.0
    flip_x: false

  - source_id: source_04
    display_name: "観測所D"
    orientation_policy: per_sample
```

### 4-3. `sources.yaml` の項目一覧

ルートは `sources` だけを持つ辞書で、値は**ちょうど4件**のリストです。

| 項目 | 必須 | 説明 |
|---|---|---|
| `source_id` | 必須 | 英数字で始まり、英数字・ハイフン・アンダースコアのみ使用可。重複不可。運用開始後は変更しないでください |
| `display_name` | 必須 | 表示名。空文字不可。出力CSV・画像・ログに使われる |
| `orientation_policy` | 必須 | `fixed` または `per_sample` |
| `north_vector` または `north_angle_deg` | fixed のみ必須 | どちらか一方。per_sample では指定不可 |
| `flip_x` | fixed のみ必須 | `true` または `false`。per_sample では指定不可 |

- `orientation_policy: fixed`: 向きが変わらない観測所です。`north_vector` または `north_angle_deg` と `flip_x` をここに登録し、全日付で再利用します。固定方向を日付別に上書きすることはできません。固定方向を変更する場合は `sources.yaml` を更新します。
- `orientation_policy: per_sample`: 向きが変わりうる観測所です。日付ごとの `comparison.yaml` に `north_vector` または `north_angle_deg` のどちらか一方と `flip_x` を入力します。テンプレートの4か所目はこの方式です。
- `sources.yaml` は、`comparison.yaml` と異なり**未対応のキーを許容しません**（追加項目があるとエラーになります）。ルートに `sources` 以外のキーを置くこともできません。
- 登録順は出力画像のタイル位置・マスク選択画面の配置順を決めます（§9、§8）。登録順を変えると、比較サマリー画像の配置も変わります。

テンプレートの方向・観測所名は架空の入力例です。実際の観測画像で北方向と鏡像の有無を確認して登録してください。

## 5. 日付ごとの準備（日付フォルダーと `comparison.yaml`）

### 5-1. 日付フォルダーを作る

入力データルートの下に `YYYY-MM-DD` 形式のフォルダーを作ります。既定の場所を使う場合の例: `source_input/2026-11-02/`。

**フォルダー名が比較日付の唯一の情報源**です。`comparison.yaml` や各サンプルには日付を書きません。実在しない日付（例: `2026-02-30`）はエラーになります。

### 5-2. 画像を置く

その日に入手できた画像だけを日付フォルダーに置きます。ファイル名は自由です。

- 対応形式: `.tif` / `.tiff` / `.fits` / `.fit` / `.fts`
- 画像の種類: 2次元のグレースケール画像（カラー画像・多チャンネル画像は対象外）
- サブフォルダー内も含めて再帰的に検索し、日付フォルダー配下にある対応形式の画像ファイル数を数えます。
- 画像が1枚もない日、または5枚以上ある日は実行できません（`samples` は1～4件のため）。

### 5-3. `comparison.yaml` を書く

`docs/templates/comparison.example.yaml` を日付フォルダーへコピーして編集します。入手できた観測所だけを記載します。`samples` の件数は日付フォルダー内の対応画像ファイル数と一致させてください。4件固定ではありません。各 `source_id` は `sources.yaml` に登録済みである必要があり、未登録IDがある場合は比較全体がエラーになります。

```yaml
# 省略可。省略すると最初に処理する画像で共通マスクを選択します（§8）。
# mask_template: "../mask_templates/default.json"

samples:
  - source_id: source_01
    image: "source_01.tif"
    pixel_scale_arcsec_per_pixel: 0.60

  - source_id: source_04
    image: "source_04.tif"
    pixel_scale_arcsec_per_pixel: 0.80
    north_angle_deg: 90.0
    flip_x: false
```

### 5-4. `comparison.yaml` の項目一覧

トップレベル:

| 項目 | 必須 | 説明 |
|---|---|---|
| `samples` | 必須 | サンプルのリスト（1～4件）。件数は日付フォルダー内の対応画像数と一致させる |
| `mask_template` | 任意 | 共通マスクのJSON。日付フォルダーからの相対パス。入力データルート配下に限る |

各サンプル（`samples` の要素）:

| 項目 | 必須 | 説明 |
|---|---|---|
| `source_id` | 必須 | `sources.yaml` に登録したID。同じ日付内で重複不可 |
| `image` | 必須 | 日付フォルダーからの相対パス。日付フォルダーの外は参照不可 |
| `pixel_scale_arcsec_per_pixel` | 必須 | 有限かつ正の数値。画像ごとに入力 |
| `north_vector` または `north_angle_deg` | per_sample のみ必須 | どちらか一方。fixed の観測所では指定不可 |
| `flip_x` | per_sample のみ必須 | `true` / `false`（真偽値）。fixed の観測所では指定不可 |

ピクセル分解能は、太陽の角半径（MIN2 の半径 × 分解能）の妥当性確認に使います。結果が 900～1000 秒角（設定で変更可）を外れると警告が出ますが、処理は継続します。X・Y 別のピクセル分解能には未対応で、等方ピクセルを前提とします。

### 5-5. 追加項目（メモなど）の扱い

`comparison.yaml` には、上の表にない**追加項目を書いても構いません**。撮影メモ・露光時間・担当者名などを、トップレベルにもサンプルの中にも記載できます。

```yaml
note: "薄雲あり。午後の画像は除外"        # トップレベルの追加項目
samples:
  - source_id: source_01
    image: "source_01.tif"
    pixel_scale_arcsec_per_pixel: 0.60
    exposure_s: 0.01                      # サンプルの追加項目
    operator: "田中"
```

- 追加項目は**解析にも出力にも使われず、無視されます**。
- 無視した項目名は、実行時に警告ログとして表示されます（`comparison.yaml の追加トップレベル項目は使用されず無視します: note` のような1行）。綴り間違いに気付くための表示で、処理は止まりません。
- 追加項目があっても、**必須項目の検査は省略されません**。たとえば `pixel_scale_arcsec_per_pixel` を `pixel_scale` と書き間違えた場合は、追加項目として無視され、必須項目の欠落としてそのサンプルがスキップされます（§13）。
- 任意項目 `mask_template` を `mask_templete` のように書き間違えると、追加項目として無視され、テンプレートなしの扱い（マスク画面を表示）になります。警告ログを確認してください。
- 追加項目の値の型は問いません（文字列・数値・リスト・辞書のいずれも可）。
- この許容は `comparison.yaml` のみです。`sources.yaml` では未対応のキーはエラーになります（§4-3）。

## 6. 実行方法

### 6-1. フォルダー選択ダイアログから

```powershell
python run.py --compare
```

フォルダー選択ダイアログは既定の `source_input/` から開きます。比較する日付フォルダーを1つ選びます。入力データが別ドライブなどにある場合は、ダイアログからその場所へ移動して選択できます。ダイアログで選択をキャンセルした場合は比較を開始せず、終了コード `2` で終了します。

### 6-2. コマンドラインで指定

```powershell
python run.py --compare source_input/2026-11-02
```

相対パスはプロジェクトルート基準です。絶対パスならリポジトリ外の任意の場所を指定できます。空白を含むパスは引用符で囲みます。選択した日付フォルダーの**親フォルダーが入力データルート**として扱われ、その直下に `sources.yaml` が必要です。日付フォルダー内には `comparison.yaml` と画像を配置します。画像は日付フォルダー内、`mask_template` は入力データルート内を指定してください。

1回の実行で処理できる日付フォルダーは**1つ**です。複数日を比較するときは日付ごとに実行してください。

### 6-3. Windows の `run.bat` から

既存の `.venv` があれば標準で使用し、なければシステムPythonを使用します。

```bat
run.bat --compare
run.bat --compare source_input\2026-11-02
run.bat --venv --compare source_input\2026-11-02
run.bat --compare "E:\SolarData\2026-11-02"
```

引数なしで `run.bat` をダブルクリックすると起動GUIが開き、単一画像／比較モードと日付フォルダーを選択できます。GUIで日付フォルダーを指定した場合は、実行前に、フォルダー名（実在する `YYYY-MM-DD`）、親フォルダーの `sources.yaml`、日付フォルダー内の `comparison.yaml` の有無を確認し、不足があればその場でメッセージを表示します（詳細な検証は従来どおり実行時に行われます）。

`python run.py`（引数なし）および `run.bat`（引数なし・GUIを使わない場合）は従来どおり単一画像モードで、動作・出力は変わりません。

### 6-4. 実行直前に表示される確認内容

入力の検証が通ると、処理開始前に次の内容が表示されます。意図どおりか確認してください。

- 比較日付（フォルダー名から取得）
- 登録観測所の一覧と、各観測所の向きの指定方式
- 各サンプルの画像名・ピクセル分解能・北方向ベクトル・北方向の角度・`flip_x`・方向の取得元（`sources.yaml` か `comparison.yaml` か）
- 入力不備でスキップされるサンプルとその理由、未提供の観測所
- 共通マスクの扱い（テンプレート指定、または最初に成功した画像で選択）

| コード | 意味 |
|---|---|
| `0` | 全体ステータスが `success` または `partial_success` |
| `1` | 全体ステータスが `failed` |
| `2` | 比較セット全体の入力エラー、またはフォルダー選択のキャンセル（処理は開始されません） |

## 7. 実行中の流れ

1. **入力検証**: `sources.yaml`・`comparison.yaml`・画像・`mask_template` を検査します。比較セット全体の不備はここで報告され、セッションは作られません。サンプル単位の不備はそのサンプルだけスキップされます。
2. **セッション作成**: 出力先（`Paths.output_folder` 配下、既定は `results/`）に `session_YYYYMMDD_HHMMSS_xxxxxx/` を作成し、ログを記録し始めます。
3. **プレビュー準備**: 有効な各画像から MIN2 で太陽中心・半径を推定します。マスク選択画面の4ペイン表示に使われます。
4. **観測所ごとの解析**: `comparison.yaml` の記載順に、周縁減光補正 → 強調 → 黒点抽出 → マスク適用 → 統計CSV出力を行います。1つが失敗しても、残りは続行します。
5. **共通マスクの確定**: テンプレートを指定していない場合、最初に成功した画像でマスクを選択し、そのマスクを共通座標の多角形として保存して残りの画像へ適用します（§8）。
6. **集計**: 比較サマリー画像の作成、座標別CSVの作成、観測所間の自動対応付け、統合CSVの作成を行い、`comparison_summary.json` を書き出します。
7. **最終確認画面**: `Display.show_final_image: true` のとき、全観測所の処理完了後に確認ウィンドウを1つだけ表示します（§9-4）。

## 8. 共通マスク

マスクは元画像の pixel 座標ではなく、**共通座標の多角形**として保存します。画像の向きが異なると、元画像上の矩形は別の画像では回転した四角形になるためです。

### 8-1. テンプレートを指定しない場合

1. 最初に正常処理される画像が編集対象になります。2×2の4ペインは `sources.yaml` の登録順で配置し、編集ペインもその観測所の登録位置に表示します。左上へ移動して表示することはありません。未提供・読み込み不能の観測所は、その登録位置にラベル付きの空スロットを表示します。
2. 編集画面で除外したい領域をドラッグします。編集画像には矩形、ほかの画像には各画像の太陽中心・半径・方向を使って変換した多角形が表示されます。
3. ドラッグ中もマスク範囲がリアルタイムに同期されます。各画像には +X / +Y（北）の方向軸が表示されるため、画像の向きを確認できます。
4. 確定すると編集画像の矩形が共通座標の多角形として保存され、残りの画像には各画像の pixel 座標へ逆変換して適用します。
5. 保存されたテンプレートは、入力データルートの `mask_templates/YYYY-MM-DD_<source_id>.json` に書き出されます（同名の既存ファイルは上書きされます）。

この方式では、`comparison.yaml` に `mask_template` を書かない限り、**前日までに作ったマスクは自動では再利用されません**。毎回、その日の最初の画像でマスクを選択します。

### 8-2. テンプレートを指定する場合

`comparison.yaml` の `mask_template` に JSON ファイルのパスを指定すると、選択画面を開かずにそのテンプレートを全画像へ適用します。既存テンプレートを別の日付で再利用できます。

```yaml
mask_template: "../mask_templates/2026-11-02_source_01.json"
```

- パスは**日付フォルダーからの相対パス**で、絶対パスは指定できません。
- 参照先は入力データルート配下に限ります（外側を指す `..` は拒否されます）。
- ファイルが存在しない場合、または内容が不正な場合は比較全体がエラーになります。

### 8-3. テンプレートの構造

```json
{
  "schema_version": 1,
  "coordinate_system": "solar_disk_normalized",
  "created_from": {
    "source_id": "source_01",
    "image": "source_01.tif"
  },
  "regions": [
    {
      "id": 1,
      "vertices": [
        [-0.25, 0.10],
        [0.15, 0.10],
        [0.15, 0.35],
        [-0.25, 0.35]
      ]
    }
  ]
}
```

`created_from` には作成元の観測所・画像・日付・太陽 geometry・北方向・`flip_x` が履歴として残ります。座標の正本は `regions` の共通座標です。`vertices` は `[X, Y]` の組で、太陽半径を 1 とした共通座標（+Y が北）です。テンプレートを手で書く場合は、座標が共通座標であり画素ではないことに注意してください。

### 8-4. マスクによる除外ルール

既定の `Mask.boundary_policy: overlap` では、マスク領域に1画素でも重なる黒点候補を候補単位で丸ごと除外します。

| `boundary_policy` | 除外される条件 |
|---|---|
| `overlap`（既定） | 黒点が除外領域に1画素でも重なる |
| `centroid` | 黒点の重心が除外領域内にある |
| `contained` | 黒点の全画素がすべての除外領域の和集合に収まる |

「1画素でも重なれば除外」は既定の `overlap` の説明であり、ほかのポリシーには当てはまりません。複数マスクに該当する候補は1回だけ除外し、該当するすべてのマスク番号を記録します。画像の外にはみ出す領域は画像内へ切り詰めて適用します。

このほか、`Mask.Rmask`（既定で有効）が、太陽半径の `radius_ratio`（既定 0.85）より外周側の黒点を除外します。マスク選択画面で選ぶ領域とは別の除外要因で、除外一覧CSVの `excluded_by_factor` で区別できます。

### 9-1. フォルダー構成

```text
results/session_YYYYMMDD_HHMMSS_xxxxxx/
├─ run_*.log
├─ run_*.json
├─ comparison_summary.json
├─ comparison_summary_raw.png
├─ comparison_summary_limb_corrected.png

└─ common_coordinates/
   ├─ comparison_sunspot_statistics.csv
   ├─ comparison_sunspot_exclusion_list.csv
```

- 未提供・スキップ・失敗した観測所の出力フォルダーは作成されません。
- 出力先（`results/`）はプロジェクトルート基準で、`Paths.output_folder` で変更できます。

### 9-2. どのファイルを何に使うか

| ファイル | 主な用途 |
|---|---|
| `comparison_summary.json` | その日の実行結果の総括。各観測所の状態・太陽中心/半径・方向・検出数・マスク・対応付け結果 |
| `comparison_summary_*.png` | 観測所間の見た目の比較（向きの確認、マスク位置の確認） |

| `image_coordinates/…/*.csv` | 各画像の画素座標での黒点位置（元画像との突き合わせ用） |
| `*_exclusion_list.csv` | マスク・Rmask などで除外した黒点とその理由 |
| `run_*.log` / `run_*.json` | 実行環境・設定・各段階のイベントの記録 |

### 9-3. CSV の座標系

- `image_coordinates/` には画像左上原点・右が +X・下が +Y の pixel 座標CSVを保存します。`common_coordinates/` には太陽中心原点・+X右・+Y北・太陽半径単位の共通座標CSVを保存します。両フォルダーは同じ階層構成で、観測所別CSVと統合CSVを含みます。
- 共通座標CSVでは重心・外接矩形を共通座標へ変換します（`centroid_x_common` / `centroid_y_common` / `bbox_x_common` / `bbox_y_common` / `bbox_width_common` / `bbox_height_common`）。面積（`area_px`）は元画像の画素数のままです。除外理由の詳細に含まれる `*_px` の列・JSONは pixel 座標のままです。
- 統合 CSV の先頭には `source_id` / `source_name` / `image` が追加されます。統合 CSV に入るのは処理に成功した観測所だけです。比較日はフォルダー名と `comparison_summary.json` で確認してください。
- 統計CSVには、共通黒点IDの列（`common_sunspot_id` / `matched_source_count` / `match_status`）が加わります（§10）。

各出力の詳細な列定義は [CSV 出力ガイド](csv_output_guide.md) を参照してください。

### 9-4. 比較サマリー画像と最終確認画面

- `comparison_summary_*.png` は Raw / 周縁減光補正 / 強調 / 二値抽出の各段階で4画像を共通方向へ回転表示した比較画像です。タイル位置は `sources.yaml` の登録順で固定され、未提供・スキップ・失敗した観測所は空スロットとして残ります。成功した画像を詰めて配置しないため、同じ観測所の位置は日付によって変わりません。各タイルの見出しには `source_id` と検出数（例: `source_01  |  2 spots`）を表示し、空スロットには理由（`Not provided` / `Skipped (invalid input)` / `Failed (see log)`）を表示します。日本語の表示名は画像に描画できないため、見出しは英数字の `source_id` のみです。元画像ファイルや解析入力画像は変更しません。
- マスク選択画面の4ペインも `sources.yaml` の登録順で固定します。編集対象は登録順の該当スロットに留め、他観測所は同期プレビュー、未提供・読み込み不能な観測所はラベル付きの空スロットで表示します。
- `Display.show_final_image: true` のとき、全観測所の処理完了後に最終確認画面を1つだけ表示します。上部の一覧から確認したい観測所を選ぶと、その1枚が大きく表示されます。単一画像モードと同じ操作（拡大・移動・履歴・表示切替）が使えます（[画像確認ダイアログ操作ガイド](image_viewer_guide.md)）。比較モードの最終確認画面には多角形マスクの塗りつぶしは表示されません。

### 9-5. `comparison_summary.json` の主な項目

| キー | 内容 |
|---|---|
| `comparison_date` | 比較日付（フォルダー名） |
| `registered_sources` | 登録4観測所（`source_id`・`display_name`・`orientation_policy`） |
| `samples` | サンプルごとの結果（`status`、検出数、スキップ・失敗の理由、角半径の警告有無） |
| `successful_sources` | 成功した観測所の詳細（太陽中心・半径・角半径、方向と変換行列、検出数、マスク領域数、出力先） |
| `mask_template` | 適用した共通マスクのJSONのパス |
| `matching` | 対応付けの結果（アルゴリズム名、許容距離、対応グループ数、対応した検出数、未対応の検出数） |

| `comparison_summary_images` | 保存した比較サマリー画像のファイル名 |
| `coordinate_csv_directories` | 座標別CSVフォルダーのパス |
| `overall_status` | 全体ステータス（§12） |
| `output_directory` | セッションフォルダーのパス |

## 10. 観測所間の自動対応付け

各観測所で検出した黒点のうち、**共通座標上の重心が近いもの**を同じ黒点とみなし、共通IDを付けます。

### 10-1. 手順

1. 観測所の全ペアについて、共通座標上の重心間距離を計算します。
2. ペアごとに、許容距離以内の組を最大数だけ選びます（ハンガリー法による一対一の割り当て）。許容距離を超える組を無理に作らず、許容内の組の数を優先します。
3. 選んだ組を、同じ観測所の候補が1つのグループに2つ以上入らない範囲で、グループへ統合します。
4. グループ内の**全候補間の最大距離**も許容距離以下である場合にだけ統合します（鎖状につながって遠い候補が混ざることを防ぎます）。
5. 2つ以上の候補を含むグループに、共通ID `CS0001` の形式で番号を付けます。番号は、グループの重心が北（+Y が大きい）にあるものから順に付き、同じ高さでは +X が小さいものが先です。
6. グループに入らなかった候補は `unmatched` です。

### 10-2. 統計CSVに加わる列

| 列名 | 内容 |
|---|---|
| `common_sunspot_id` | 観測所間で対応付けられた共通ID。例: `CS0001`。未対応は空欄 |
| `matched_source_count` | 同じIDに含まれる観測所数。未対応候補は `1` |
| `match_status` | `matched` または `unmatched` |

### 10-3. 許容距離の考え方

既定の対応許容距離は `Comparison.matching.tolerance_normalized: 0.025` です。**太陽半径の 0.025 倍**であり、秒角ではありません。太陽の角半径が960秒角なら約24秒角に当たります。値を大きくすると対応しやすくなりますが、別々の黒点を同じ黒点と誤って対応付ける可能性が高まります。小さくすると誤対応は減りますが、北方向・MIN2の太陽中心のわずかな誤差でも対応が外れます。

> 自動対応付けは**重心距離による初期対応**です。観測時刻の差・太陽自転・差動回転の補正、および人手による確認の代わりにはなりません。実観測画像で一致・不一致を確認してください。

## 11. 設定（`src/config.yaml`）

比較モード専用の設定は `Comparison` セクションです。

```yaml
Comparison:
  matching:
    tolerance_normalized: 0.025   # 太陽半径に対する比（秒角ではない）
  angular_radius_warning_arcsec:
    min: 900.0                    # 秒角
    max: 1000.0                   # 秒角
```

| 設定 | 既定値 | 説明 |
|---|---|---|
| `Comparison.matching.tolerance_normalized` | `0.025` | 観測所間の対応許容距離（太陽半径比）。正の有限値 |
| `Comparison.angular_radius_warning_arcsec.min` | `900.0` | 太陽角半径の警告下限（秒角）。0以上 |
| `Comparison.angular_radius_warning_arcsec.max` | `1000.0` | 太陽角半径の警告上限（秒角）。`min` 以上 |

実際に使われた値は `comparison_summary.json` の `comparison_settings` に記録されます。数値以外・NaN・無限大、負の値、`min` > `max` はエラーになります。

比較モードにも、単一画像モードと共通の次の設定が使われます。

| 設定 | 説明 |
|---|---|
| `Mask.boundary_policy` | マスクによる除外条件（§8-4） |
| `Mask.Rmask.enabled` / `radius_ratio` | 外周側の黒点除外（既定で有効・0.85） |
| `Display.show_final_image` | 最終確認画面を表示するか |
| `Paths.output_folder` | 出力先フォルダー（既定 `results`） |
| `MIN2` | 太陽中心・半径の推定パラメーター。全観測所に同じ値が使われます |
| `LimbDarkingResolution` / 強調・抽出の各設定 | 画像処理のパラメーター。全観測所に同じ値が使われます |

## 12. 実行ステータス

サンプル単位:

| 状態 | 意味 |
|---|---|
| `success` | 処理に成功 |
| `not_provided` | `comparison.yaml` に記載がない。エラーではありません |
| `skipped_invalid_input` | 入力不備により、そのサンプルだけスキップ |
| `failed_processing` | 処理中に例外が発生。他のサンプルは続行 |

全体:

| 状態 | 条件 | 終了コード |
|---|---|---|
| `success` | 登録4観測所すべてが入力され、すべて成功 | 0 |
| `partial_success` | 1件以上成功し、未提供・スキップ・失敗がある | 0 |
| `failed` | 有効サンプルが0件、または全サンプルが失敗 | 1 |
| 入力エラー | 実行開始前の比較セット全体のエラー | 2 |

観測所が3つしか入手できない日は、正常でも `partial_success`（`not_provided` を含む）になります。

## 13. エラーと対処

座標・パラメータの単位を確認するときは、先に §3 の単位一覧と注意事項を参照してください。

**比較セット全体のエラー**（実行開始前に報告され、セッションは作られません。終了コード 2）

| 原因 | 対処 |
|---|---|
| `sources.yaml` がない・構文不正・4か所でない・ID重複・未対応のキーがある・方向設定が不正 | `sources.yaml` を修正（テンプレートからコピー） |
| 日付フォルダーがない・フォルダー名が `YYYY-MM-DD` でない・実在しない日付 | フォルダー名を修正 |
| `comparison.yaml` がない・構文不正・ルートが辞書でない | `comparison.yaml` を作成・修正 |
| `samples` がない・空・5件以上 | 1～4件にする |
| 日付フォルダー内の対応画像数と `samples` 件数が異なる | 画像と `samples` を1件ずつ対応させる（サブフォルダー内の画像も数えられます） |
| `comparison.yaml` の `source_id` が `sources.yaml` に未登録 | `sources.yaml` に登録するか、IDを修正 |
| `mask_template` で指定したファイルがない・絶対パス・入力データルートの外・内容が不正 | パスを修正するか項目を削除 |

**サンプル単位のスキップ**（該当サンプルのみ。残りは処理されます）

| 原因 | 対処 |
|---|---|
| 同じ `source_id` が複数行ある | 該当IDの全行がスキップされるため、1行にする |
| `image` がない・空・絶対パス・日付フォルダーの外を参照 | 日付フォルダーからの相対パスにする |
| 画像がない・対応外形式・読み込めない・2次元でない | ファイルを確認 |
| 分解能が未入力、0以下、NaN、無限大 | 正の数値を入力（キー名の綴りも確認） |
| `per_sample` で方向項目が欠落・不正 | `north_vector` または `north_angle_deg` のどちらかと `flip_x` を入力 |
| `fixed` で日付別の方向を指定 | 日付側から削除し、向きを変える場合は `sources.yaml` を更新 |

`comparison.yaml` の**追加項目はエラーになりません**（§5-5）。キー名の綴り間違いは、警告ログと、必須項目の欠落エラーで気付けます。

**警告（処理は継続）**

| 表示 | 意味と対処 |
|---|---|
| 追加項目を無視した旨の警告 | `comparison.yaml` に使われない項目がある。意図したメモなら問題なし。綴り間違いなら修正 |
| 太陽角半径が暫定範囲外 | `pixel_scale_arcsec_per_pixel` の誤り、または MIN2 の半径推定の誤りの可能性。画像と分解能を確認 |

## 14. よくある質問

**Q. 同じ観測所の画像が2枚ある日はどうすればよいですか。**
A. 1回の実行では、観測所ごとに1サンプルです。1日に複数の画像がある場合は、使う画像だけを日付フォルダーに置くか、日付フォルダーを分けて別々に実行してください。同じ `source_id` を複数行書くと、その観測所の全行がスキップされます。

**Q. 3観測所分の画像しかない日は実行できますか。**
A. できます。入手できた観測所だけを `samples` に書き、画像数と件数をそろえてください。未提供の観測所は `not_provided` として記録され、全体は `partial_success` になります。

**Q. 前日と同じマスクを使いたいです。**
A. 前日に自動保存された `mask_templates/YYYY-MM-DD_<source_id>.json` を、`comparison.yaml` の `mask_template` で指定してください（§8-2）。

**Q. 観測所の向きが日によって変わります。**
A. その観測所を `orientation_policy: per_sample` にし、日付ごとの `comparison.yaml` に向きを書きます。向きが固定なら `fixed` にして `sources.yaml` に登録すると、日付ごとの入力が不要になります。

**Q. `comparison.yaml` にメモを書いたら動かなくなりますか。**
A. 動作に影響しません。追加項目は無視され、警告ログに項目名が表示されるだけです（§5-5）。

**Q. 黒点が観測所間で対応付けられません。**
A. まず `comparison_summary_raw.png` で向き（§3-4）を確認してください。向きが合っているのに対応しない場合は、MIN2 の太陽中心・半径の誤差が考えられます。必要に応じて `Comparison.matching.tolerance_normalized` を調整し（§10-3）、結果を目視で確認してください。

**Q. CSVの座標をそのままグラフにすると上下が逆になります。**
A. `*_px` は +Y が下向きの画素座標です。共通座標の `*_common` は +Y が北（上）です。グラフにするときは用途に合う方のCSVを使ってください（§3）。

## 15. 注意事項

- パラメータの単位を取り違えないよう、§3 の単位一覧を確認してください。特に画素と共通座標、+Y の向き、`north_angle_deg` の角度基準に注意してください。
- 北方向ベクトルまたは角度の入力誤差は、マスク位置と黒点座標の両方に影響します。`north_angle_deg` は0°が右、90°が上で、反時計回りに増加します。
- `flip_x` が誤っていると、黒点位置が左右反対になります。新しい観測所の設定後は、既知の黒点が観測所間で一致するか確認してください（§3-4）。
- MIN2 の太陽中心・半径が不正確な画像では、共通座標も不正確になります。角半径の警告や出力画像を確認してください。
- ピクセル分解能はユーザー入力値です。誤りは角度スケールの確認や将来の物理単位換算に影響します。
- 画像ごとの観測時刻は保存せず、太陽自転・差動回転の補正は行いません。観測時刻が大きく離れた画像どうしの対応付けは参考値としてください。
- 固定観測所の向きを変更するときは、`sources.yaml` を更新してください。過去の実行ログには、その実行で実際に使われた向きが残ります。
- 同じ日付で再実行すると、マスクテンプレート `mask_templates/YYYY-MM-DD_<source_id>.json` が上書きされる場合があります。残したいテンプレートは別名でコピーしておいてください。

## 16. 暫定仕様・未確定事項

| 事項 | 現在の動作 |
|---|---|
| 観測所の正式ID・表示名 | `source_01` ～ `source_04` の仮ID・仮名称。実際の値に変更可能 |
| 3観測所の北方向・`flip_x` | テンプレートの架空値。実際の値の登録が必要 |
| 共通 +X の向き | `flip_x: false` で「北を上にしたときの画像右方向」。天文学上の東西との対応は未確定 |
| ピクセル分解能 | 画像ごとに単一の `arcsec/pixel` を入力。X・Y別は未対応 |
| マスクテンプレート共有 | 日付フォルダーで指定。省略時は基準画像から作成 |
| 対応付け許容距離 | `src/config.yaml` の `Comparison.matching.tolerance_normalized` で変更可能。既定値は 0.025（太陽半径比。秒角ではない） |
| 太陽角半径の警告範囲 | `Comparison.angular_radius_warning_arcsec.min/max` で変更可能。既定値は 900～1000 秒角 |
| 比較 CSV の指標 | 画像座標と共通座標の重心・外接矩形・面積。面積はpixel単位 |
| `comparison.yaml` の追加項目 | 許容し、無視する（警告ログのみ）。`sources.yaml` は従来どおり未対応キーをエラーとする |

未対応の後続課題は、北方向の自動推定、heliographic座標、太陽自転・差動回転補正、異方ピクセル、複数日付の一括実行（`--compare-all`）です。自動対応付けは重心距離による初期対応で、物理的な黒点追跡や時刻差補正ではありません。

人工画像での単体テストは追加していますが、実観測画像での MIN2 と北方向入力の妥当性、および各観測所の実際の向き・`flip_x` は、実データで確認する必要があります。自動対応付けの許容距離は観測分解能や MIN2 の誤差を含む実データで妥当性を確認してください。
