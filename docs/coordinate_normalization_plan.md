# 太陽画像の座標正規化・共通マスク機能 変更計画書

## 1. 目的

複数の観測所で撮影された太陽画像について、画像上の太陽の向きと大きさが異なることによるマスク範囲・黒点座標の比較困難を解消する。

本変更では、**画像そのものを回転・反転・リサイズしない**。各画像の太陽中心・太陽半径と、ユーザーが入力する太陽北方向ベクトルを使い、マスクと黒点座標だけを共通座標系へ変換する。

## 2. 対象範囲

### 実装する機能

- 画像ごとの太陽北方向ベクトル入力と値の検証
- MIN2 が推定する太陽中心・太陽半径の共通利用
- 太陽中心を原点、北を +Y、太陽半径を 1 とする座標変換
- 共通座標系でのマスク保存・再利用
- 共通マスクを各画像のピクセル座標へ逆変換して黒点候補を除外
- 黒点 CSV への共通座標の追加
- 変換条件・マスク条件のログ保存
- 既存ピクセル座標および既存マスク動作との互換性維持

### 今回は実装しない機能

- 画像データ自体の回転・反転・リサイズ・再サンプリング
- 画像の見た目を変更するプレビュー機能
- 北方向の自動推定、FITS/WCS による姿勢推定
- 黒点特徴点を使った画像同士の自動位置合わせ
- 太陽表面の heliographic latitude / longitude への変換
- 観測時刻差による太陽自転・差動回転の補正
- 視線方向や太陽面傾斜を含めた三次元的な表面位置の復元

本機能が出力する座標は、太陽円盤の**投影画像面上の相対座標**であり、太陽表面の緯度・経度そのものではない。

## 3. 座標系と入力仕様

### 3.1 元画像の座標系

現状を維持する。

- 原点：画像左上
- +X：画像右方向
- +Y：画像下方向
- 単位：pixel

### 3.2 共通座標系

- 原点：MIN2 が推定した太陽中心
- +Y：ユーザーが指定した太陽北方向
- +X：北方向に直交する方向。左右反転設定によって符号を確定する
- 単位：太陽半径を 1 とした無次元座標
- 太陽中心：(0, 0)、太陽の見かけの縁：おおむね原点からの距離 1

マスクや座標が太陽円盤外に存在する場合もあるため、座標を [-1, 1] に制限しない。

### 3.3 北方向ベクトル

画像ごとに、画像ピクセル座標系での北方向ベクトル (north_x, north_y) を入力する。

- 右が +X、下が +Y。例えば (0, -1) は画像上方向、(1, 0) は画像右方向。
- ベクトルの長さは使用せず、方向だけを使う。
- (0, 0)、NaN、無限大は無効として、理由を表示して処理を中止する。
- 画像上の北方向を示す点を指定する方式にする場合は、その点から MIN2 の太陽中心を引いてベクトルにする。

初期実装では、各画像の処理時に PyQt の設定ダイアログまたは設定入力欄で X・Y 成分を入力する。入力値は実行ログに保存し、再実行時に追跡できるようにする。設定ファイルに既定値を持たせる場合も、画像ごとの入力値を優先する。

### 3.4 左右反転

**北方向ベクトルだけでは、画像が鏡像になっているか判断できない。** 北方向とは独立した flip_x 設定を用意する。

flip_x の既定値は false とし、観測装置の光学系や観測所の画像規約に応じて true を指定できるようにする。共通 +X を天文学上の東・西のどちらに対応させるかは、実装着手前に決め、全観測所で統一する。

## 4. 座標変換仕様

### 4.1 使用する値

| 記号 | 意味 |
|---|---|
| C = (cx, cy) | MIN2 が推定した太陽中心 |
| R | MIN2 が推定した太陽半径 [pixel] |
| N = (nx, ny) | ユーザーが入力した北方向ベクトル |
| P = (x, y) | 変換対象のピクセル座標 |

R は有限かつ正、北方向ベクトルは有限かつ長さが 0 より大きいことを検証する。

### 4.2 回転角

画像座標の Y 軸は下向きなので、次の角度を使う。

    theta = pi / 2 + atan2(ny, nx)

内部ではラジアンで保持する。北が画像上方向 (0, -1) の場合、theta は 0 となる。

### 4.3 元画像から共通座標へ

    dx = x - cx
    dy = y - cy

    X = (cos(theta) * dx + sin(theta) * dy) / R
    Y = (sin(theta) * dx - cos(theta) * dy) / R

    if flip_x:
        X = -X

画像の回転・反転・補間は行わず、点の座標だけを変換する。変換行列は次のとおり。

    A = [[ cos(theta),  sin(theta)],
         [ sin(theta), -cos(theta)]]

    q = A * (P - C) / R

flip_x が true の場合は、変換後の X 成分だけを反転する。

### 4.4 逆変換

共通座標で保存したマスク頂点を画像へ戻すときは、順変換と逆変換を独立した関数として実装する。回転・反転行列は直交行列であるため、逆行列は転置行列から求められる。順変換・逆変換の往復誤差を単体テストする。

## 5. 太陽半径とピクセル分解能

### 5.1 MIN2 の半径を主に使う理由

今回の主目的は、異なる画像に写る太陽円盤上の同じ相対位置を同じ座標で扱うことである。各画像で MIN2 が推定した太陽半径 R [pixel] を使い、太陽半径を 1 に正規化する。

例えば、画像ごとの太陽半径が 500 pixel と 800 pixel であっても、太陽中心からの相対位置を共通の無次元座標で表せる。

### 5.2 ピクセル分解能の使い道

ピクセル分解能 s [arcsec/pixel] は、相対座標の主スケールではなく、角度スケールの取得・整合性確認・将来の物理単位出力に使用する。

    solar_angular_radius_arcsec = solar_radius_px * pixel_scale_arcsec_per_pixel

ピクセル分解能が不明でも、MIN2 の中心・半径が有効なら相対座標変換は可能とする。ただし角度単位の値は出力しない。

X・Y 方向のピクセル分解能が異なる場合、現在の円近似と一様スケーリングでは正確に扱えない。初期版では等方ピクセルを前提とし、X・Y 分解能が与えられた場合は一致を検証する。不一致が許容範囲を超えるデータは警告または処理不可とし、異方性補正は別途設計する。

### 5.3 MIN2 の結果を共有する

現在は limb_darkening_resolution.polynomialFit() 内で MIN2 を呼び出し、中心・半径を取得しているが、後段処理から同じ値を再利用できる構造になっていない。

変更後は、MIN2 の結果を SolarGeometry 相当のデータ構造（中心 X・Y、半径、必要な推定情報）として取得し、周縁減光補正と座標変換の双方へ渡す。同じ画像に対して MIN2 を重複実行しない。

既存の polynomialFit() の呼び出し互換性を維持するため、geometry 引数は任意引数とする。geometry が渡されない既存の利用方法では、従来どおり関数内で取得できるようにする。

## 6. 共通マスク

### 6.1 保存形式

マスクを元画像の矩形 (x, y, width, height) のまま共有しない。基準画像で選択した矩形の四隅を共通座標へ変換し、共通座標系上の多角形として保存する。

元画像上の矩形は、回転補正後の共通座標では一般に四角形となる。将来の拡張性を考え、頂点数を固定しない多角形形式にする。

保存ファイル案：mask_template.json

    {
      "schema_version": 1,
      "coordinate_system": "solar_disk_normalized",
      "regions": [
        {
          "id": 1,
          "vertices": [[-0.25, 0.10], [0.15, 0.10], [0.15, 0.35], [-0.25, 0.35]]
        }
      ]
    }

上記の座標値は形式説明用である。テンプレートには元画像の pixel 座標を正本として保存しない。作成元画像、作成時の太陽 geometry、北方向ベクトル、反転設定などは履歴情報として保存する。

### 6.2 作成・再利用

初期版では既存のマスク選択 UI を利用する。基準画像上で矩形を選択し、その四隅を共通座標へ変換してテンプレートに保存する。同じテンプレートを別の観測画像で読み込み、共通領域として再利用する。

今回、マスク UI 自体を画像回転表示に対応させることは必須要件にしない。

### 6.3 適用

各画像で、共通座標の多角形頂点を逆変換してピクセル座標へ戻し、ラベル画像上に多角形マスクを適用する。

- 元画像の画素値は変更しない。
- 既存の「マスクに1画素でも重なる黒点候補ラベルを候補単位で除外する」動作を維持する。
- 頂点は浮動小数点で保持し、ラスタライズ時にのみ画素格子へ変換する。
- 画像外の領域はラスタライズ時にクリップする。正規化座標自体は切り詰めない。
- マスクごとの重複候補数、除外ラベル、適用範囲を従来どおりログに記録する。

共通マスク機能が無効の場合は、既存の pixel 矩形マスクをそのまま利用し、従来結果を変えない。

## 7. 黒点 CSV の変更

既存の pixel 座標列は削除・改名しない。元画像での再確認や既存スクリプトとの互換性のために残し、共通座標の重心列を追加する。

sunspot_statistics.csv と sunspot_exclusion_list.csv に次の列を追加する。

| 列名 | 内容 |
|---|---|
| centroid_x_normalized | 共通座標系に変換した重心 X |
| centroid_y_normalized | 共通座標系に変換した重心 Y |

centroid_x_px / centroid_y_px は従来どおり画像左上原点の pixel 座標とする。

既存の bbox_x_px / bbox_y_px / bbox_width_px / bbox_height_px も元画像上の外接矩形として残す。回転補正後の形状は矩形とは限らないため、これらを共通座標の外接矩形と誤認させない。共通座標での形状比較は、初期版では必須とせず、必要になった段階で輪郭頂点や共通座標の外接範囲を追加する。

任意の追加指標として area_px / (pi * R**2) による円盤面積比を検討できるが、初期必須項目は重心の共通座標化とする。面積の物理換算はピクセル分解能の信頼性を確認してから追加する。

## 8. 設定とログ

### 8.1 設定案

    ImageOrientation:
      enabled: false
      north_vector:
        x: 0.0
        y: -1.0
      flip_x: false

    SolarCoordinate:
      normalization: solar_radius
      pixel_scale_arcsec_per_pixel: null

    Mask:
      coordinate_system: pixel
      template_path: null

設定の既定値では従来動作を維持する。共通座標機能を有効にし、画像ごとの北方向入力が有効な場合にのみ変換を適用する。

### 8.2 ログに残す情報

- MIN2 の太陽中心 (cx, cy) と半径 R
- 入力された北方向ベクトルと正規化後の方向
- 回転角 theta
- flip_x
- 変換行列と座標系のバージョン
- ピクセル分解能（入力された場合）
- マスクテンプレートのパス・schema version
- 共通マスク／従来 pixel マスクのどちらを使用したか
- 変換後のマスク頂点、重複候補数、除外候補ラベル

## 10. 実装段階と完了条件

### Phase 1：太陽 geometry の共通化

1. MIN2 の結果を SolarGeometry として取得する。
2. main.py から周縁減光補正と後段処理へ同じ geometry を渡す。
3. 従来と同じ画像・設定で補正結果が変化しないことを確認する。

完了条件：同じ画像に対して MIN2 を重複実行せず、既存の補正・検出が維持される。

### Phase 2：北方向入力と座標変換

1. 画像ごとの北方向ベクトル入力を追加する。
2. flip_x を独立して指定可能にする。
3. 順変換・逆変換を独立モジュールに実装する。
4. 変換パラメータをログに保存する。

完了条件：既知の方向ベクトルで北が必ず共通 +Y となり、往復変換誤差が許容範囲内に収まる。

### Phase 3：共通マスクテンプレート

1. 基準画像で選択した矩形 ROI の四隅を共通座標へ変換する。
2. 多角形 JSON として保存・読み込みする。
3. 各画像で逆変換し、多角形マスクをラベル画像へ適用する。
4. 既存 pixel 矩形マスクを維持する。

完了条件：回転角度・太陽半径の異なるテスト画像でも、同じ共通領域が除外される。

### Phase 4：CSV とログ

1. 残存黒点・除外黒点の両 CSV に共通座標の重心列を追加する。
2. CSV ガイドを更新する。
3. geometry・方向・反転・マスクテンプレート情報をログに保存する。

完了条件：既存列の意味を変えず、新列と変換条件をログから追跡できる。

### Phase 5：総合検証

1. 回転角・太陽半径・画像中心が異なる人工画像で共通座標を比較する。
2. 左右反転あり・なしを検証する。
3. 実観測画像で MIN2 と北方向入力の妥当性を確認する。
4. 既定設定で従来動作が維持されることを確認する。
5. Ruff、Basedpyright、既存 CI を通過させる。

## 11. テスト計画

### 座標変換

- 北が画像上 (0, -1) のとき、変換後の北が (0, +1) になる。
- 北が右 (1, 0)、下 (0, 1)、左 (-1, 0)、任意の斜め方向の場合も同様に成立する。
- ベクトルの長さだけを変えても変換結果が変わらない。
- flip_x は X の符号だけを変え、Y を変えない。
- 太陽中心が常に (0, 0) になる。
- 太陽半径上の点は原点からの距離がおおむね 1 になる。
- 順変換と逆変換で元の pixel 座標に戻る。
- ゼロベクトル、非有限値、半径 0 以下を拒否する。

### 観測所間比較

同じ正規化座標にある人工黒点を、中心・半径・回転角の異なる画像へ配置する。画像ごとの北方向を入力し、変換後の黒点座標が一致することを確認する。左右反転画像では正しい flip_x を与えた場合に一致することを確認する。

### マスク

- 基準画像で作成したマスクが、別の向き・半径の画像でも同じ共通領域に対応する。
- 回転後の矩形が多角形として正しく表現される。
- マスク境界付近の画素処理が一貫する。
- 複数マスクに重なる候補は1回だけ除外し、該当する全マスク ID を記録する。
- 画像端・画像外へはみ出すマスクを安全に処理する。
- 従来の pixel 矩形マスクのテスト結果が変わらない。

### 回帰

- 共通座標機能を無効にした場合、従来のマスク範囲・黒点数・pixel CSV が変わらない。
- geometry の共有後も周縁減光補正画像が変わらない。
- CSV の既存列・除外一覧・ログに後方互換性がある。
- Ruff、Basedpyright、既存 CI を通過する。

## 12. 利用者から見た機能変化

### 変更前

- マスクは画像左上原点の pixel 座標で指定する。
- 観測所ごとに太陽の向き・大きさが異なり、同じマスク座標をそのまま再利用できない。
- 黒点 CSV の座標は画像ごとの pixel 座標なので、観測所間で直接比較しにくい。

### 変更後

- 画像ごとに太陽北方向ベクトルを入力し、必要に応じて左右反転を指定する。
- MIN2 の太陽中心・半径を基準に、中心が原点、北が +Y、太陽半径が 1 の共通座標へ変換する。
- マスクを共通座標の多角形として保存し、別の観測画像へ再利用できる。
- 黒点 CSV には従来 pixel 座標に加えて共通座標の重心が記録される。
- 元画像の画素値・向き・大きさは変化せず、画像回転による補間の影響を受けない。

### 利用上の注意

- 北方向ベクトルの入力誤差はマスク位置と黒点座標の両方に影響する。
- 北方向だけでは左右反転を判断できないため、flip_x を正しく設定する必要がある。
- MIN2 の中心・半径が不正確な画像では、正規化座標も不正確になる。
- 太陽半径による正規化は円盤上の相対位置比較に適するが、pixel あたりの実寸や角度サイズを直接表さない。
- 本機能だけでは太陽表面の緯度・経度や、異なる観測時刻の同一黒点位置は求められない。

## 13. 実装着手前に確定する事項

1. 共通 +X を天文学上の東・西のどちらにするか。
2. flip_x を画像ごとに入力するか、観測装置・観測所プロファイルとして保存するか。
3. マスクテンプレートをどの基準画像で作成し、どの観測データへ適用するか。
4. 北方向ベクトルを入力する画面と、値の単位・符号の表示方法。
5. ピクセル分解能が不明な画像、または X・Y 分解能が異なる画像の許容条件。
6. 共通座標上の黒点形状・面積比較を初期版に含めるか。初期版では重心座標を必須とし、形状比較は後続段階とする案を推奨する。

特に共通 +X の向きと左右反転規約は、観測所間比較を始める前に確定する。
